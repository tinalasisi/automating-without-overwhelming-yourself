Step by step

5 steps · 45 min

  1. Build the Google Form 5 min

    • New Google Form. Question titles = the CSV header. The header is the form.
    • Pick short answer, checkbox or dropdown to match the data.
    • Link a responses Sheet: Responses tab → Sheets icon.
    • Submit two or three responses by hand. Watch one land.

  2. Fill it with dummies 5 min

    • Fast: import the ready-made CSV. On the responses Sheet: File → Import → Append to current sheet.
    • Or make your own with U-M GPT. Paste this, then paste your CSV header row after it.
    U-M GPT: generate dummy responses
    I am building a test copy of an intake form so I can develop an automation without touching real data. Here are the form's questions, as a CSV header. Generate 15 realistic fake responses as CSV rows with the same columns. Use fake names and @example.edu addresses. Make them varied and messy the way real submissions are: include one duplicate submission from the same person, one response with a required field left blank, one that answers two questions in one box, and one that is clearly outside what the form is for. Do not use any real person or organisation.

    Imported rows don't fire the form-submit trigger. That's fine. Step 4 handles it.

  3. IDEA pass on your sandbox 10 min

    IIdentify

    What does "done" look like for one submission?

    DDocument

    Source: the responses Sheet. Transformation: which fields become which output. Output: a doc, an email, a status column, a row in another sheet. What's fixed? What varies?

    EExperiment

    The smallest version.

    AAdjust

    What breaks?

  4. Have AI write the Apps Script 20 min

    Ask for two shapes

    Trigger on submit

    onFormSubmit: one new response, one output.

    Test it: submit a response by hand.

    Process the backlog

    Walks every row with an empty Status. Does the work. Writes "done" and a timestamp.

    You need this one: imported rows never fire the trigger.

    The prompt shape

    • Describe the columns.
    • Paste three sample rows.
    • Say what output you want.
    • Ask for the code and a plain-English explanation of each section.
    Prompt skeleton: fill in the brackets
    I have a Google Sheet of form responses (fake test data).
The columns are: [list each column and what it holds].

Here are three sample rows:
[paste three rows]

For each row I want: [the output: a status column, a doc, an email draft, a row in another sheet].

Write a Google Apps Script with two functions:
1. One that runs on form submit and handles the new response.
2. One that processes the backlog: every row whose Status column is empty. It does the work, then writes "done" and a timestamp.

Give me the code and a plain-English explanation of each section.

    Before you run it, three checks

    1. What is the loop?
    2. Where would a new field go?
    3. What tools and permissions does it need?
    Then run it. Paste it into Extensions → Apps Script and run. Authorize when asked. That screen is the permissions lesson, live. Read it: it lists every key you hand over.
    Speaker notes

    The authorization prompt is the payoff of the permissions talk at 2:30. "It acts as you." Ask a team to read their consent screen aloud.

  5. Hit the planted problems 5 min

    The duplicate The blank field Two answers in one box

    For each one, decide: a rule, or manual review?

    Add a needs review status, with a reason, rather than guessing.

No form in your project?

Skip the form. Paste the dummy file into U-M GPT: the requests inbox, the drive listing, or the two sheets. Add a short spec of what you want for each item. Ask for a table back.

Then the same IDEA pass, and the same traps check.

House rules and tool choice: 3 · Tools of the trade

The house rules I used for the demos
CLAUDE.md / AGENTS.md
# House rules for this folder

Everything in this folder is dummy data made for a workshop. Treat it as if it were real.

- Work only inside this folder. Don't read or write anywhere else.
- The CSV files you were given are originals. Never edit them; write new files next to them.
- Before you run any code, explain in plain English what it will do.
- Put exact checks (duplicates, blanks, formats, dates) in code. Use your own judgment only where I ask
  for it, and say which is which.
- When a row doesn't fit the rules, mark it "needs review" with a reason. Don't guess.
- Never send email, post, or upload anything.
