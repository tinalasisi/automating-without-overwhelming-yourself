Anthropic

A coding agent that works in a project folder.

Today's demos

Anthropic

The agent mode in the Claude app, for knowledge work on your files.

No terminal

The Claude Desktop app. Since July 2026, also on claude.ai on the web and on mobile.

It asks before it acts

Claude Code

Permission modes. Default asks before every edit and command. Auto uses classifiers to approve some steps for you.

Since August 14, Auto is the default on Pro, Max and Team plans. Check which mode you're in.

Claude Cowork

Asks permission for actions, like Claude Code. It reaches only the folders you connected, with the permissions you set.

Codex

Two dials. Sandbox: read-only, workspace-write or danger-full-access. Approval: on-request or never.

The default preset, Auto, is workspace-write plus on-request. Network is off by default. --yolo turns off both dials; OpenAI marks it not recommended.

Both products have something called “Auto,” and they mean different things. Start where it asks the most, and loosen one notch at a time.

House rules

1 min
CLAUDE.md

Claude Code reads it at the start of every session: commands, conventions, project rules.

AGENTS.md

Codex reads it before it starts work, from your global settings down to the current folder. The closest file wins.

Cowork

Keep the same file in the connected folder and ask it to read that first.

This is the file in today's demo folder. No code in it: an SOP in plain English.

03_demos/CLAUDE.md (also saved as AGENTS.md)
# House rules for this folder

Everything in this folder is dummy data made for a workshop. Treat it as if it were real.

- Work only inside this folder. Don't read or write anywhere else.
- The CSV files you were given are originals. Never edit them; write new files next to them.
- Before you run any code, explain in plain English what it will do.
- Put exact checks (duplicates, blanks, formats, dates) in code. Use your own judgment only where I ask
  for it, and say which is which.
- When a row doesn't fit the rules, mark it "needs review" with a reason. Don't guess.
- Never send email, post, or upload anything.

Ways to run an automation

4 min

Five ways, from “you run it” to “it runs itself.” The further down, the less you watch.

You run itIt runs itself
  1. A

    By hand, in a session

    You ask, you watch every step, you say yes or no. The smallest useful unit starts here.

    Claude Code's /loop repeats a prompt inside an open session until a goal is met, for up to about three days.

    Laptop on, you're at itClaude Code · Cowork · Codex
  2. B

    A trigger inside a tool you already use

    Google Apps Script. On form submit runs when someone responds to a form. Time-driven runs anywhere from every minute to once a month; a 9 AM trigger fires between 9 and 10, then keeps that time.

    It runs as the person who created the trigger, so any email it sends comes from that account.

    Laptop can be closedToday's hands-on, Track A
  3. C

    Scheduled on your own computer

    cron runs a command on a timetable. On a Mac, Apple recommends launchd instead. The command can be a script, or an agent run without a chat window: claude -p "…" or codex exec "…".

    Only while the computer is on and awake. A launchd job missed during sleep runs when the Mac wakes; a cron job waits for its next time.

    Laptop must be on
  4. D

    Scheduled tasks built into the apps

    • Claude Code, desktop scheduled tasks: on your machine, awake with the Desktop app open. As often as every minute, with your local files and a permission mode for each task.
    • Claude Code routines: in Anthropic's cloud. On a schedule (at most hourly), from an API call, or on GitHub events. No local files. Set up at claude.ai/code/routines or with /schedule.
    • Claude Cowork scheduled tasks: /schedule. They run in the cloud and keep going when the Desktop app is closed, but reach your connected folders only while it is open.
    • Codex scheduled tasks (formerly Automations): under Scheduled in the ChatGPT desktop app, which works as an inbox. On the desktop they can use your project folder, with the computer on and the app running. Made on the web, they use uploads and connected tools, not your folders.
    Laptop: depends where it runs
  5. E

    In the cloud: GitHub Actions

    A workflow file in a GitHub repository, run on GitHub's machines on a schedule or on events such as a pull request. Claude Code and Codex each have an official Action: anthropics/claude-code-action and openai/codex-action.

    API keys live in repository secrets. Every run uses the key, and API use costs money.

    Laptop can be closed

Reading a cron line

0minute
9hour
*day of month
*month
1day of week

0 9 * * 1 means 9:00 every Monday.

One crontab line
# minute hour day-of-month month day-of-week  command
0 9 * * 1  /Users/you/intake/run-triage.sh
Before you point cron at an agent
  • claude -p is Claude Code's non-interactive mode, so cron or launchd can run it.
  • codex exec starts read-only. Add --sandbox workspace-write to let it edit. It expects a Git repository unless you pass --skip-git-repo-check, and only the final answer goes to standard output, so you can save it to a file.
  • OpenAI lists scheduled jobs as a use for codex exec; its docs don't show a crontab line.

A GitHub Actions schedule

.github/workflows/weekly-check.yml
name: Weekly check
on:
  schedule:
    # By default, cron time is UTC. 13:00 UTC is 9:00
    # in Michigan during daylight saving time.
    - cron: '0 13 * * 1'
jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: python3 check.py
        env:
          API_KEY: ${{ secrets.API_KEY }}  # a repository secret
Good to know
  • The shortest schedule is every 5 minutes. It runs on the latest commit of the default branch.
  • GitHub now also accepts a timezone: line next to the cron line.
  • Runs can be delayed at busy times, such as the top of the hour. In a public repository, schedules switch off after 60 days with no activity.
  • Add a key under Settings → Secrets and variables → Actions → New repository secret. Values read through secrets are masked in logs.
  • openai/codex-action@v1 needs openai-api-key from a secret, plus a prompt or prompt-file. OpenAI's example runs on pull requests, not on a schedule.

Which setup for your project?

2 min

7 of 11 client projects involve sensitive data or an NDA. Answer four questions.

1. Is the data sensitive or under an NDA?
2. Does it live in Google Workspace (Forms, Sheets, Drive)?
3. Does it need to run on files on a computer?
4. Does it need to run on its own?

Recommendation

Answer all four questions. 0 of 4 answered.

How the chooser decides
  1. Files on a computer? Claude Code or Codex, or Cowork if you'd rather skip the terminal. On its own: a desktop scheduled task, or cron or launchd, with the computer on. If it also lives in Google, ask whether Apps Script is simpler.
  2. Otherwise, in Google Workspace? Apps Script, written with an AI assistant and read by you. On its own: an on-form-submit or time-driven trigger.
  3. Otherwise, sensitive data? An approved chat assistant, U-M GPT or Maizey, by hand. No schedule until a tool is approved for that data.
  4. Otherwise, on its own? A cloud schedule: a Claude Code routine, a Cowork scheduled task, a Codex scheduled task made on the web, or GitHub Actions.
  5. Otherwise? Cowork or a chat assistant, by hand, when you need it.
  6. Sensitive data adds a caution to every answer: build on dummy data, and real data goes in only if the client and U-M approve the tool.
